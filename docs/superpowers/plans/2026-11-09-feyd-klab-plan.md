# Фейд Клаб Implementation Plan

**Goal:** Собрать локальный учебный комплект сайта и интеграций по ТЗ-09/2026 и довести подключаемые сервисы до фактических ресурсов после получения входа.

**Architecture:** Статические HTML/CSS/JS страницы публикуются из GitHub на Vercel. Отдельный Google Apps Script принимает заявки и пишет их в таблицу; GA4 получает события только после успешной записи. UTM, отчёт и сервисные инструкции ведутся в `docs/`.

**Tech Stack:** HTML, CSS, vanilla JavaScript, Google Apps Script, Google Sheets, GA4, GitHub, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-09-feyd-klab-design.md`

## Global Constraints

- Результат сайта — статические HTML, CSS и JavaScript, которые открываются без сборки; React/Next.js и другие framework-сборки не принимаются.
- 8 страниц: `index.html`, `services.html`, `masters.html`, `works.html`, `style-quiz.html`, `contacts.html`, `thanks.html`, `privacy.html`, плюс `404.html`.
- Адаптивность проверяется на 375, 768 и 1280 px; без горизонтальной прокрутки; кнопки минимум 44×44 px.
- Цвета: `#141414`, `#B8862B`, `#EDE6DA`; шрифты Oswald и Inter; все интерфейсы на русском.
- Никаких вымышленных цен, адресов или часов; использовать только данные ТЗ.
- GA4 не получает имя, телефон или email; `generate_lead` отправляется только после ответа приёмника `ok: true`.
- Слот — ближайшие 14 дней, 60 минут 10:00–21:00; занятые значения отключены; согласие обязательно и по умолчанию снято.
- По просьбе пользователя автоматизированные тесты не создавать и не запускать; выполнять короткую ручную проверку страниц и интеграционных точек.
- Секреты Google, Instagram, GitHub и иных кабинетов не сохранять в репозитории.

## Tasks

### Task 1: Статический сайт

**Files:** 8 HTML-страниц, `404.html`, `css/style.css`, `js/analytics.js`, `js/form.js`, локальные изображения, favicon и PDF прайса.

- Создать общие шапку/подвал, метаданные и Open Graph для каждой страницы.
- Сверстать блоки страниц в указанном ТЗ порядке, с реальными данными и мобильно-дружественными кнопками.
- Реализовать фильтры мастеров/работ, тест из четырёх вопросов, копирование FIRST20, календарь слотов, согласие, отправку формы и `.ics`.
- Отправлять обязательные события и параметры через единый `js/analytics.js`; заменить Measurement ID после создания GA4.
- Убедиться визуально в корректном отображении на 375/768/1280 px без автоматизированного набора тестов.

### Task 2: Apps Script и таблица

**Files:** `apps-script/Code.gs`, `apps-script/README.md`, схемы листов в документации.

- Принимать POST и валидировать обязательные поля, форматы телефона/email, перечисления и длины строк.
- Под защитой блокировки отклонять повторный `request_id`; дописывать `created_at` и `status=new`, игнорировать присланный статус.
- Хранить ID таблицы в Script Properties; задокументировать веб-деплой, разрешения и конфигурацию без ключей в коде.
- После доступа создать листы `leads`, `utm`, `ga4_traffic`, `ga4_leads` и проверить реальную запись тестовой заявки.

### Task 3: UTM, графика и документация

**Files:** `docs/prompts.md`, `docs/events.md`, `docs/utm.csv`, `docs/images.md`, `docs/report.md`, `docs/SETUP.md`, `docs/qr-u-12.png`, `docs/afisha.pdf`, `README.md`, `.gitignore`.

- Внести U-01—U-12 с метками, назначениями и ссылками на тестовый адрес; реальные короткие URL и URL публикаций обновить после создания аккаунтов.
- Описать 20 событий, пользовательские параметры, ключевые события и источники фото.
- Оставить аналитические выводы пустыми до поступления реальных проверочных данных; не фабриковать screenshots.
- Сделать QR и афишу из полной U-12 ссылки, если доступны библиотеки.
- Начать README с таблицы ссылок и ясно показать незаполненные внешние значения.

### Task 4: Подключение сервисов и публикация

**Files:** конфиг GA4, обновляемый UTM-реестр и README; реальные сервисы в аккаунтах пользователя.

- После входа создать GA4 с зоной GMT+03:00/валютой RUB, включить расширенную статистику и зарегистрировать ключевые события/custom dimensions.
- Создать Google Sheet и Web App Apps Script; вставить endpoint в конфиг; выдать заказчику Viewer по указанному email.
- Создать тестовые каналы/публикации и ManyChat automation после предоставления страниц/Reel и проверить фактическую доступность.
- Создать GitHub repo `tz-09-barbershop-feyd-klab`, добавить не менее 10 осмысленных коммитов и привязать Vercel к `main`.
- Сохранить фактические результаты и снимки; в отчёте указать, что не получилось выполнить.
