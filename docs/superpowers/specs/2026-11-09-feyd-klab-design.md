# Проектный дизайн: Фейд Клаб

## Цель

Собрать учебный проект барбершопа по ТЗ-09/2026: статический сайт из восьми страниц и 404, запись на время, отправку лидов в Google Таблицу, UTM-разметку, события GA4 и комплект материалов для отчётности и публикации.

## Контекст и границы

В рабочей папке изначально был только PDF ТЗ. Заказчик подтвердил, что это учебный кейс, следует оставить вымышленные реквизиты из документа и подключать аккаунты только как тестовые ресурсы. Внешние сервисы требуют входа владельца аккаунта; локальные коды и инструкции подготовить заранее. Не размещать реальные персональные данные.

## Архитектура

- `*.html`, `css/style.css`, `js/analytics.js`, `js/form.js`: обычные статические файлы без сборки и фреймворка; все страницы используют общий визуальный каркас.
- `apps-script/Code.gs`: валидирующий идемпотентный POST-приёмник, пишет в лист `leads`; идентификатор таблицы задаётся через Script Properties.
- `docs/`: журнал промптов, события GA4, UTM-реестр, источники медиа, отчёт и инструкции подключения кабинетов.
- `screens/`: место для фактических снимков DebugView и каналов; не подменять снимки фиктивными изображениями.
- GitHub → Vercel: публичный статический репозиторий и автопубликация из `main` после входа владельца.

## Визуальное направление

Соблюдать фирменные цвета `#141414`, `#B8862B`, `#EDE6DA`, Oswald и Inter. Крупная типографика и фотография реальной фактуры стрижки задают первый экран; тонкая латунная «карта формы» связывает портрет, галерею и тест. Движение ограничить короткими проявлениями и состояниями фильтров; уважать `prefers-reduced-motion`. Все изображения — локальные оптимизированные WebP/JPEG с `alt` и источниками в `docs/images.md`.

## Поток записи и данных

1. Ссылки из UTM-реестра ведут на страницу назначения; метки сохраняются в `sessionStorage`.
2. Форма валидирует имя, телефон, услугу, уровень мастера, слот и согласие; слот — дата в ближайшие 14 дней с целым часовым шагом 10:00–21:00.
3. `js/form.js` отправляет URL-encoded запрос в Apps Script и показывает номер заявки/страницу благодарности только после `ok: true`.
4. При успешном ответе отправляется `generate_lead`, без имени, телефона и email в GA4. Ошибки дают `form_error`.
5. Таблица хранит сведения заявки и её UTM-источник со статусами, перечисленными в ТЗ.

## Внешние подключения

GA4, Google Sheets/Apps Script, ManyChat/Instagram, GitHub и Vercel настраиваются в тестовых аккаунтах пользователя. Код допускает заполнение идентификаторов и URL через конфиг. Без входа нельзя заявлять о создании ресурса, Live-автоматизации, публикации, реальном приёме формы. Для публикаций потребуются приглашения в тестовые страницы/каналы и URL тестового Reel; секреты не коммитить.

## Проверка и сдача

Автоматизированные тесты не добавлять по просьбе пользователя. Перед сдачей сверить состав страниц и файлов с ТЗ, открыть локально страницы, визуально осмотреть 375/768/1280, проверить браузерную консоль и доступность ссылок/слотов. Для GA4, таблиц и ManyChat сохранять только реальные снимки после входа и завершения настройки; недоступные внешние действия перечислить в README.
